## PR title
Add task_runs table and prov task start/complete commands for runner lifecycle tracking

## Status
complete

## Summary
Adds runner-level task tracking to provenance. A new migration creates the `task_runs` table and adds a nullable `prompt_events.task_run_id` foreign key. New storage functions create, complete, fetch and list task runs. A new `prov task start|complete` CLI writes straight to SQLite, so it works even when the daemon is not running. The Claude Code PreToolUse/PostToolUse hooks now pass `AI_PROVENANCE_TASK_RUN_ID` through to `capture-hook` as `task_run_id`, and `capture-hook` saves it on the event row. `InitDatabase` now sets `PRAGMA busy_timeout=5000`. While testing, I found that the existing `capture-hook` tests were flaky on `main` (about 1 in 5 runs failed), and the new tests made failures more frequent. The cause was a race: the session_start message and the prompt event go to the daemon on separate connections, and the daemon could handle the prompt event before the session row existed. The event then failed its foreign key check and was dropped. I fixed this by making the client wait until the daemon has finished each message before sending the next.

## Changes
- `internal/storage/migrations/000002_task_runs.{up,down}.sql`: `task_runs` table and indexes as specified, plus `prompt_events.task_run_id` and its index.
- `internal/storage/db.go`: `PRAGMA busy_timeout=5000` after the WAL pragma; on error the DB is closed and an error returned.
- `internal/storage/task_runs.go`: `TaskRun` struct; `CreateTaskRun` (makes a v4 UUID and start time if missing); `CompleteTaskRun` with the exact signature from the spec; `CompleteTaskRunWith` (also sets `diff_stored` and allows a NULL `verify_pass`); `GetTaskRun`; `ListTaskRuns` (newest first, optional task filter, `limit <= 0` means no limit); `NewUUID`. Completing an unknown run ID returns `ErrNotFound`.
- `internal/storage/events.go`: new `PromptEvent.TaskRunID` field. It is stored as NULL when empty and read back by `GetPromptEvent` and `ListPromptEvents`.
- `cmd/prov/task.go` and `main.go`:
  - `prov task start` checks its required flags and prints the UUID on stdout.
  - `prov task complete` checks the outcome against the allowed list and parses `--verify-pass` and `--diff-stored` as `true|false` values.
  - If `--verify-pass` is omitted, `verify_pass` stays NULL.
  - Both commands create the database if it does not exist yet.
- `cmd/prov/hooks/claude-tool-{pre,post}.py`: add `task_run_id` from the environment variable when it is set and not empty.
- `cmd/prov/commands.go`:
  - `captureHook` forwards `task_run_id` on the event.
  - `sendMessageToDaemon` now closes its write side and waits (up to 2s) for the daemon to close the connection, which fixes the ordering race.
- `CHANGELOG.md` entry.

## Needs human attention
- **Daemon client change:** the `sendMessageToDaemon` fix touches existing daemon client behaviour. Each hook call now blocks until the daemon has handled the message, which is normally a few milliseconds and at most 2s. Please confirm this is acceptable for the hook latency budget.
- **Unknown run IDs drop events:** `prompt_events.task_run_id` is a real foreign key. If `AI_PROVENANCE_TASK_RUN_ID` holds an ID that is not in `task_runs`, the daemon's insert fails (when foreign keys are enforced on that connection) and the event is dropped. This matches the spec's "valid UUID" assumption, but a mistyped env var would silently lose events.

## Proposed follow-ups
- **Title:** Apply SQLite PRAGMAs per connection via DSN instead of db.Exec | **Why:** `PRAGMA foreign_keys`/`busy_timeout` set via `db.Exec` only affect one pooled connection; other connections in `database/sql`'s pool won't have them
- **Title:** Make GetPromptEvent/ListPromptEvents tolerate NULL text columns | **Why:** Rows with NULL `model_version` etc. (e.g. inserted by older code or raw SQL) cause scan errors in storage getters
- **Title:** Add prov task list/show commands backed by ListTaskRuns | **Why:** Task runs are recorded but there is no CLI to inspect them or their linked prompt events
