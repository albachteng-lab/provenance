## PR title
Run CI on the self-hosted homelab runner and trigger on push and pull requests

## Status
complete

## Summary
Replaced `.github/workflows/ci.yml` with the standard homelab CI pattern used by the org's other Go repos. The workflow now runs a single `ci` job on `[self-hosted, homelab]` inside a `golang:1.25` container, triggers on both `push` and `pull_request`, and runs gofmt, `go vet`, `go test -race`, and a build of `./cmd/prov`. The GitHub-hosted `test`, `lint` (golangci-lint), and `build` jobs and the codecov upload were removed.

## Changes
- `.github/workflows/ci.yml`: rewritten to the homelab template (self-hosted runner, golang:1.25 container, push+PR triggers, single `ci` job with format/vet/test/build steps).
- Removed the golangci-lint job and the codecov upload step.

## Testing
- Ran the same steps locally: `gofmt -l .` (clean), `go vet ./...` (ok), `go test -race ./...` (all packages pass), `go build ./...` (ok).
- `~/.runner/hooks/verify-completion.sh` passes.
- The workflow only runs for real on the PR, since it needs the self-hosted runner; the PR's CI run confirms the last criterion.
